# 拾集 · 登录与账号细节

更新日期：2026-10-20
状态：用户要求补齐的桌面端体验；具体字段规则与文案为实施建议。

## 1. 当前共识

- 首版只考虑桌面端，当前三端布局先保留。
- 增量补齐登录、昵称、头像、账号菜单和个人资料，避免只有商品与后台列表。
- 买家商城保留搜索和商品流；商家、平台继续使用左导航工作区。
- 设计讨论中的角色切换仅用于演示，正式产品根据账户权限显示入口。
- 普通用户统一注册登录，默认进入买家商城；头像菜单中的“商家中心”按开店状态进入介绍、申请、进度或工作台。
- 按 D051 首版一个账号最多拥有一家店，保留独立店铺成员关系用于扩展；不增加多店切换或员工管理。平台管理员复用账号与角色关联的具体表方案仍在 [数据库讨论稿](13-数据库设计.md) 中评审，管理员权限继续由受控流程授予。

## 2. 登录页

采用独立页面：顶部品牌与返回商城，左侧品牌介绍，右侧登录卡片。品牌区沿用当前暖橙色与主视觉，文案可以是“欢迎回来，淘点好东西”。

登录卡片包含：

- 标题与登录 / 注册切换。
- 登录账号、密码，有明确字段标签。
- 密码显示或隐藏按钮。
- 主登录按钮，以及返回商城入口。
- 就地错误反馈和提交中的状态。

首版采用账号密码。验证码、扫码、第三方登录、找回密码后续再做，未实现的入口不显示为可用按钮。示意中的演示账号要明确标识，不能当作正式登录机制。

访客可继续浏览、搜索和看商品；加购、结算、个人数据及有会话记录的导购需要登录。引导登录时记住原页面、所选规格与操作上下文，成功后返回；继续写操作前再次核验最新商品状态。

登录表单不提供“选择管理员就获得管理员权限”的选项。正式身份由账号权限与店铺成员关系决定；商家审核通过后出现工作台入口。

### 登录后的去向

买家与商家共用账号体系。正常注册或登录统一进入买家商城，有有效购物上下文时返回原页面。首版不在登录页要求选择“买家 / 商家”，也不另设面向普通用户的商家注册流程。

| 进入方式 | 成功后去向 |
| --- | --- |
| 商城登录，或从购物操作被引导登录 | 返回原购物页面与有效操作上下文；没有原页面时进入买家首页 |
| 普通注册或无上下文登录 | 进入买家首页；即使已有店铺也不自动强制切换工作区 |
| 已登录后从头像点击商家中心 | 按开店申请及店铺状态选择目标页面，见下表 |
| 平台管理入口登录且有管理员权限 | 直接进入平台管理台 |

商家中心的页面分发：

| 账号的开店状态 | 展示内容 |
| --- | --- |
| 未申请 | 开店权益、准备资料、流程、常见问题及免费开店按钮 |
| 草稿 | 继续填写申请，保留店名、标识、类目与简介 |
| 待审核 | 审核进度，不进入可经营工作台 |
| 已驳回 | 原因与修改重提入口 |
| 已通过且店铺正常 | 直接进入店铺工作台，不重复展示开店宣传 |
| 店铺被停用 | 显示限制原因的商家工作区，按既定规则处理已有订单 |

首次点击商家中心不直接创建店铺；用户在介绍页确认“免费开店”后才进入申请。实际目标由服务端身份、申请状态和店铺成员关系决定，不能通过 URL 或前端场景切换获得权限。需重新登录时先恢复认证，再重新校验站内目标与当前权限。

从买家商城进入商家工作台无需再次登录；从商家端返回商城也沿用同一登录态。管理员使用独立受控入口，此处指进入平台管理页面的地址与权限，不要求另建登录页面或账号系统。正式产品不展示原型顶部的场景切换栏。

### 管理入口与登录页面的区别（D052 已确认）

用户已确认“打开管理入口 → 共用登录页 → 输入账号密码 → 后端检查管理员角色 → 进入管理台”。管理入口决定目标页面，登录页面验证当前账号，服务端角色决定能否进入及执行操作；具体认证会话技术和角色字段随工程确认。

首版共用登录页和认证流程；商城、商家工作台和平台管理仍是已有范围内的不同业务页面，不额外拆成三个工程或复制三套账号密码逻辑：

| 进入场景 | 已确认行为 |
| --- | --- |
| 普通账号直接登录 | 没有原操作上下文时进入买家首页，保留既有流程 |
| 已登录后从头像进入商家中心 | 复用当前登录态，按申请和店铺状态进入介绍、申请、进度或工作台 |
| 未登录直接访问平台管理入口 | 跳到共用登录页，保留允许的站内目标；成功后检查当前平台角色再决定是否进入 |
| 已登录且有平台管理权限 | 进入平台管理页面，并在每次管理接口调用时检查权限 |
| 已登录但没有平台管理权限 | 显示无权限；知道地址或更改前端参数不能获得管理权限 |

例如 `/admin → /login?redirect=/admin → 校验权限 → /admin` 只是正式工程的路由示意，不是当前新增的可用地址；原型仍沿用既有 hash 路由。返回目标需限制为允许的站内地址，不能任意外跳；普通公开注册不能通过该参数取得角色。无需在登录页设置“选管理员即可登录”的身份选择。

将来如需给管理端登录页增加“平台管理”标题或更换外观，也可复用同一登录组件，属于可选展示调整；本轮不修改 Demo 或额外新增页面。平台管理的审批、商品处理等业务页面仍需按原计划实现。

公开平台参考：2026-10-18 查阅 [淘宝开放平台：BC 客服聊天能力中的千牛平台说明](https://developer.alibaba.com/docs/doc.htm?articleId=122234&docType=1&treeId=829)，其说明移动千牛可使用开通店铺的淘宝账号登录；[AI 员工配置文档中的千牛体验步骤](https://developer.alibaba.com/docs/doc.htm?articleId=121831&docType=1&treeId=837) 展示淘宝登录与授权进入移动千牛的路径。它们支持账号可跨业务入口复用的说明，不证明所有设备共享同一登录态，也不作为淘宝/天猫平台员工内部管理系统的实现依据。本轮未实际登录这些系统。

## 3. 注册页

复用登录页壳和表单位置，填写登录账号、密码、确认密码，昵称可选填。注册成功生成固定用户 ID，分配默认昵称和头像，并进入登录态。

注册购物车方案已按 D061 确认：仅保留共享 cart_items，直接按 user_id 归属，零条商品项即为空购物车，注册时无需写入购物车记录，首次加购才创建商品项。不会为每个用户动态建物理表，也不预建地址、订单或未申请店铺。详细字段与私有接口继续讨论，见 [数据库讨论稿](13-数据库设计.md)；本轮未修改注册实现。

普通注册成功后进入原购物页面或买家首页，再从头像菜单进入商家中心了解并申请开店。
新账号先拥有基础购物能力，商家经营权限在入驻审核通过后取得。开店入口不能跳过审核直接赋予发布商品与处理订单的权限。管理员账号由系统配置或受控管理流程建立，不通过公开注册获得。

账号重复、两次密码不一致、必填为空等在对应字段附近说明。密码不进入日志、分析事件或示意状态持久化；交互示意不接收真实账户密码。

## 4. 名字与头像分清楚

| 对象 | 用途 | 是否可编辑 |
| --- | --- | --- |
| 登录账号 | 登录与识别账号，例如 taoyou_001 | 首版只读 |
| 用户 ID | 系统生成的稳定标识 | 不可编辑 |
| 昵称 | 页面展示，例如拾光同学 | 可编辑，可重名 |
| 个人头像 | 识别当前登录的人 | 可更换，有默认头像 |
| 店铺名称与 Logo | 对外代表店铺 | 店铺设置中维护 |
| 平台名称与管理员标记 | 明确当前管理范围 | 普通用户不能修改或取得该身份 |

昵称不是权限依据，修改昵称不改变订单归属。建议昵称去除首尾空格，限制展示长度，不能为空；具体长度在表单规范中确定。

默认头像可用首字圆形图案或少量内置头像。正式资料页支持更换图片与预览，建议先支持 JPG / PNG、大小不超过 2 MB；复杂裁剪工具后续再考虑。上传失败或取消编辑都保留原头像。

头像图片加载失败时使用默认图案，不能留下破损图片。长昵称在顶栏适当截断，个人资料页完整显示。

## 5. 三端身份区域

### 买家

顶栏左上角保留独立品牌区；右上角由头像、昵称和账号菜单组成，访客显示登录 / 注册。购物车移到页面右侧的收放工具栏，头像左侧不再放购物车按钮。搜索框独立放在下一行。个人中心顶部再次展示头像、昵称与基础账户信息。

当前会话原型菜单：个人资料、我的订单、收货地址、消息中心、商家中心、退出登录。地址与消息已提供本地模拟，正式模块仍待开发。“商家中心”名称保持一致，未申请时展示开店介绍，已有申请或店铺时按状态进入对应页面。

### 商家

工作台顶部同时呈现店铺名称与个人头像昵称，例如“好物生活馆 / 林店长 / 商家”。左侧品牌区可以展示店铺 Logo。

账号菜单包含个人资料、店铺设置、返回商城、退出。店铺资料与个人资料分别保存；更换个人头像不影响店铺 Logo。

### 平台管理员

顶部明确显示平台管理、管理员头像昵称及角色标记。菜单保留个人资料、返回商城和退出，避免与普通商家后台混淆。

### 菜单行为

点击头像或昵称展开，重复点击、点击外部或按 Escape 关闭；菜单可用键盘操作。菜单不能被商品卡片或后台表格遮挡。

## 6. 个人资料页

沿用当前桌面页面壳，表单展示：头像及更换入口、昵称输入框、只读登录账号、只读用户 ID，底部保存和取消。

「保存资料 / 取消」按钮等宽等高、文字居中；当前原型共用 112 × 40 px，容器空间不足时整项换行，不按文字长度分别缩放。

编辑中的值与已保存资料分开。保存成功后同步更新当前账号的顶栏、个人中心等位置；取消恢复原值。保存失败保留草稿并说明原因，不能先显示成功。

买家与商家使用同一账号时共享个人资料，店铺信息独立；示意可使用不同演示账号展示三种身份。密码修改属于后续账号安全功能，不在本轮示意中增加无效入口。

## 7. 登录与退出状态

| 状态 | 页面反馈 |
| --- | --- |
| 访客 | 可浏览搜索，顶栏显示登录 / 注册 |
| 输入不完整 | 在字段旁提示缺项 |
| 登录中 | 按钮显示处理中并防重复提交 |
| 账号或密码错误 | 统一提示，保留账号字段 |
| 网络或服务异常 | 说明失败并允许重试 |
| 登录成功 | 普通账号进入买家首页或原有效购物上下文；管理员受控入口按权限进入后台 |
| 登录过期 | D062：暂停写入、保留原账号当前页面内存表单，重新认证原账号后核验权限/编辑冲突再继续 |
| 当前账号无权限 | 显示无权限与返回入口，不进入对应后台 |
| 退出登录 | 回到访客商城，清理当前会话与私有页面缓存 |

退出不删除服务端购物车或历史订单，重新登录本人账号后可读取；切换账号不共享购物车、地址或订单。演示可以本地模拟状态，但不能把演示通过视为后端认证已实现。

D062 确认编辑中遇到 401 不立即清空表单/强制完整刷新，保留当前账号的编辑值、资源/素材 ID 和临时关联键；多个并发 401 合并一次登录引导，复用共用登录流程。恢复后必须比较 user_id；原账号才可继续，新账号/主动退出清除原账号私有内存。密码和会话凭证不放入恢复表单。

重新认证后读取当前权限、资源和编辑/库存状态，不能拿新的编辑令牌静默覆盖旧表单与其他人的修改；不确定是否已成功的写入按原键/查询恢复，下单和付款不自动重新发送。素材已不可用只提示重新选择并保留其他输入。当前运行会话内保留不承诺跨刷新、关闭或崩溃恢复；已保存草稿按服务端回显。Cookie/JWT、续期/refresh 和期限仍待确认，本轮未改 Demo 或实现认证。

## 8. 其他需要体现的细节

- 当前栏目、页标题、店铺状态和当前身份保持一致。
- 头像昵称统一从当前用户资料读取，不在各页面各写一份。
- 用户昵称、店铺名过长时有可读的展示方式。
- 保存成功、加购成功和操作失败有短反馈，避免重复弹窗打断。
- 列表空数据和加载失败分开呈现。
- 密码显隐不改变字段内容；切走登录页或完成登录后清空密码。
- 个人资料头像、店铺 Logo、商品主图复用图片能力，保持各自归属。
- 浏览器标题采用“当前页面 - 拾集”，站点图标沿用品牌标识。
- 商品详情和后台编辑页提供面包屑或明确的返回列表入口，保留原筛选条件。
- 金额、日期和订单状态的显示格式统一，时间按平台时区呈现。
- 登录和资料页只展示真实可用的操作，尚未接入的功能不使用空链接占位。

## 9. 验收重点

1. 三端都能辨认当前账号；商家账号与店铺身份清楚分开。
2. 登录注册字段校验、错误、提交中与成功反馈完整。
3. 从加购引导登录后，回到正确商品和规格上下文。
4. 资料保存会同步顶栏，取消不改变已保存资料。
5. 退出或切换账号后，不残留上一账号的私有内容。
6. 首版不以手机端页面、手机导航或移动适配作为验收项。
7. 普通账号注册登录默认进入买家商城，即使已有店铺也不强制切换商家端。
8. 未申请时点击商家中心先展示权益与流程；点击免费开店后进入申请。草稿、待审、驳回和已开店均有对应去向。
9. 买家与商家身份共用个人资料和登录态；审核通过后才取得店铺经营权限，平台权限不通过入口选择获取。

交互示意先展示默认头像选择；真正的图片上传和身份验证在正式工程中实现并验收。

原型的固定演示账号登录、资料与购物交互，以及商家中心完整状态路径已做过浏览器检查。逐项进度见 [原型进度与文档维护](09-原型进度与文档维护.md)；这些检查不代表正式后端认证、上传或资源权限已经实现。

2026-10-18 增加“状态示例”中的登录过期演示：重新登录固定演示身份后返回原页面。地址仅使用虚构信息；订单保存提交时的地址，后来编辑或删除地址簿不会改写旧订单。正式身份隔离、服务端会话过期和地址权限尚未验收。
