# 拾集 · Agent 接口预留

更新日期：2026-10-20  
状态：已确认暂不开发 Agent，仅预留接入边界；下列为商城查询接口的契约草案，尚未实现、启动或完成接口验收。最终路径与字段随正式工程核对，并记录到 OpenAPI。

商城全量接口草案现以 [OpenAPI](openapi.json) 为主，[导入说明与旧版参考](16-接口文档.md) 供查阅（D063）。D062 确认同组合新 ID 再售及其他三项行为，公开 SKU 查询仍只公开有效启用项，不恢复旧 SKU；本页维护查询及 Agent 权限边界，不逐字段重复维护。其余契约随开发细化，查询边界变化时同步；推荐、购物车、交易和平台接口不自动获得 Agent 调用授权。

## 1. 当前范围

第一版按当前桌面原型落实买家、商家和平台的商城功能。商城服务设计成可通过规范 API 查询，后续 Agent 可复用这些业务能力。

现在不创建 Agent 服务、工具执行循环、模型调用、提示词、对话界面、悬浮球、流式接口或会话/运行记录表；不为 Agent 增加常驻容器。这里的“预留”是定义输入输出、数据来源与权限边界，实际查询接口随商城后端开发实现。

普通商品查询尽量同时服务商城页面和后续 Agent，避免复制一套商品、价格或库存逻辑。后续启用 Agent 时再增加工具适配层及受限调用身份；接入前普通商城可独立运行。

## 2. 预留查询能力

下列路径为设计草案，不是当前可访问的网址。

| 能力 | 方法与路径草案 | 主要输入 | 输出范围 |
| --- | --- | --- | --- |
| 商品搜索与筛选 | `GET /api/v1/products` | `keyword`、`category_id`、`store_id`、`min_price`、`max_price`、`sort`、`page`、`page_size`、可选 `feed_token` | 公开在售商品卡片、结果上下文计数与分页 |
| 商品详情 / 下架状态 | `GET /api/v1/products/{product_id}` | 商品 ID | 公开在售详情；D058 的商家自主下架场景仅返回最小下架状态和公开店铺资料 |
| 最新 SKU 价格与库存 | `POST /api/v1/skus/availability/batch` | 唯一 SKU ID 列表，1–20 项 | 当前价格、可售库存、售罄/不可售状态和查询时间；只读，不占库存 |
| 店铺公开资料 | `GET /api/v1/stores/{store_id}` | 店铺 ID | 店名、标识、简介与公开状态；不返回联系人、成员和审核材料 |
| 分类 | `GET /api/v1/categories` | 可选父分类 ID | 启用的分类及层级；不提供管理写入 |

第一版工程优先实现页面本身所需的查询，再完成批量 SKU 查询以便以后核对候选价格库存；不要求搭建 Agent 才能验收这些 API。

## 3. 通用契约

- 使用 `/api/v1`，JSON 字段采用 `snake_case`；实体 ID 按不透明字符串传输，不能从 ID 推断权限。
- 金额为整数分，币种 `CNY`。例如人民币 59 元为 `5900`；价格筛选参数也以分为单位，前端负责把输入的元转换成分。
- D060 确认最终展示价优先取商家选填值，未填/清空时自动取 SKU 最低价。自动分支沿用 D054：先纳入有效启用且售价为正的 SKU，有可售库存时汇总有货项最低/最高价；全售罄时回退为有效启用项参考范围并返回 `SOLD_OUT`；无有效启用项不进正常列表。商家自填价不改变库存资格，具体规格成交价必须通过详情或 SKU 查询核对。P035 建议价格筛选/排序按最终展示价统一，但自填分支的排序和标签规则尚待确认，不能将旧版仅用 `min_price` 的契约视为最终定稿。
- `sort` 草案：`default`、`price_asc`、`price_desc`、`newest`；按 D055，`newest` 使用首次成功发布的 `published_at` 倒序，修改标题/价格或重新上架不重置；同值使用稳定 ID 作为次级排序。`page` 从 1 开始，`page_size` 默认 12、上限 50。无匹配或超出最后页返回空 `items` 与准确的结果上下文 `total`，不悄悄返回第一页；列表含 `has_more` 和可空 `feed_token`。
- P040 补充稳定翻页：feed_token 绑定有序候选、筛选/排序及 page_size，不只是随机种子；影响资格或明确排序的已有候选变更使上下文失效，返回 `409 / FEED_EXPIRED` 保留筛选请刷新，不用当前 OFFSET 补位造成重漏。新增候选主动刷新后纳入，当前有效报价仍重新读取；存储/期限及校验成本待实现选择，完整说明见接口文档 2.2。
- 时间用带时区的 ISO 8601 字符串，服务端生成 `checked_at`；查询结果不构成库存预留，提交订单时再次校验。
- 返回结构与业务实体分离，公开 DTO 使用字段白名单，不直接返回数据库对象。未知属性不编造，数组允许为空，可缺省事实明确为 `null` 或未提供。
- 普通公开查询沿用商城浏览权限和可见性规则；未来受限工具身份与普通用户身份分别管理，不给模型使用管理员令牌。身份传递方式在 Agent 启用阶段确定。

2026-10-19 D060 更新 D054：`cover_image` 仍来自商家指定的排序首图；候选响应新增 `display_price` 与 `display_price_source`，区分商家填写值和自动最低价。`min_price` / `max_price` 仍派生自实际 SKU，不以商家填写值覆盖。自动分支异价标“起”，自填分支的标签及价格过滤/排序见 P035 待确认；一旦确定须在最终分页前执行同一口径。商家选填原值可由候选 `products.display_price_override` 保存，字段名/SQL 类型未冻结。缓存需覆盖填写值修改/清空、SKU 改价/启停和库存变化。详情所选规格、购物车及结算仍采用实际 SKU 售价。具体规则见 [数据库设计 3.6](13-数据库设计.md)，实际 API 与 Demo 尚未实现或验收。

### 商品列表响应示例

以下仅为虚构契约示例；图片路径为占位，并非当前可访问的资源。字段名称与类型仍待正式 OpenAPI 冻结，实际图片地址和商品资料由可信数据生成。

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {
    "items": [
      {
        "product_id": "product_lamp",
        "name": "折叠台灯",
        "category_id": "category_home",
        "cover_image": "/media/demo/lamp-main.webp",
        "store": {
          "store_id": "store_home",
          "name": "好物生活馆"
        },
        "display_price": 5900,
        "display_price_source": "AUTO",
        "min_price": 5900,
        "max_price": 7900,
        "currency": "CNY",
        "stock_status": "IN_STOCK"
      }
    ],
    "page": 1,
    "page_size": 12,
    "total": 1,
    "has_more": false,
    "feed_token": "feed_demo_search"
  },
  "request_id": "request_demo_search"
}
```

详情字段草案：`product_id`、`name`、`category_id`、`store`、`description`、有来源的 `attributes`、`images`、`skus`。图片按顺序返回，SKU 使用稳定 ID、属性组合、当前价格和可售状态；未来 Agent 从 ID 构建前端路由，不让模型自由拼接任意外部链接。

按 D055，详情规格图片来自该 SKU 可选关联的本商品图片；未绑定或引用失效时返回/采用商品主图回退。服务端校验素材可见性与商品归属，不能据客户端传入图片地址任意关联；具体图片响应结构在正式 OpenAPI 中细化。列表 `cover_image` 不因此改为随机 SKU 图片，详情默认选中哪个 SKU 仍待讨论。草稿保存与回显属于商家权限接口，不扩展此处的公开查询范围。

### SKU 批量查询示例

```json
{"sku_ids": ["sku_lamp_white_usb"]}
```

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {
    "items": [
      {
        "sku_id": "sku_lamp_white_usb",
        "product_id": "product_lamp",
        "price": 5900,
        "currency": "CNY",
        "available_stock": 8,
        "status": "IN_STOCK"
      }
    ],
    "checked_at": "2026-10-18T08:00:00Z"
  },
  "request_id": "request_demo_stock"
}
```

SKU 可售但库存为 0 时返回 `SOLD_OUT`、`available_stock: 0`，仍可展示。不存在、SKU 停用、商品下架、被平台限制或所属店铺停用等不公开项统一仅返回请求中的 `sku_id` 与 `status: NOT_AVAILABLE`，不附价格、库存或内部限制原因；响应保持输入 ID 顺序。输入列表重复、为空或超过上限时返回参数错误，不在查询中创建任何库存占用。

D057 已更新 D056 临时文案：库存为零仍显示已售罄，被替换旧规格在原购物车显示“所选商品不能购买”、商品图变灰，点击进入原店铺且不可结算；原购物车不改绑新 SKU。已确认的保存方案为停用并保留旧 SKU、为新组合建立新 SKU。公开查询的 `NOT_AVAILABLE` 不因此附带旧商品私有信息；原店铺链接由购物车权限查询的可信归属生成，仍检查店铺可见性。完整购物车私有响应结构及字段待后续设计，本轮仅同步契约边界。

## 4. 状态、权限与错误

公开列表只返回正常店铺中可展示的在售商品；草稿、平台限制和停用店铺数据不进入普通搜索。除下述 D058 自主下架最小状态分支外，公开详情不可见时返回统一 `404`，避免暴露内部管理信息。管理端和商家自己的查询使用各自权限接口，不扩展普通商品查询的可见范围。

D058 为曾公开发布、店铺正常且无平台限制的商家自主下架商品补充最小状态分支，更新此前全部不可见详情统一 404 的草案。下列 `200` JSON 为状态响应候选，具体字段待正式 OpenAPI 冻结；该分支只用于渲染“商品已下架”状态页，不返回购买用 SKU、当前价格/库存或内部下架原因。草稿、平台限制、店铺停用及不存在仍返回统一 404，不通过下架页公开其内部状态。

```json
{
  "code": "SUCCESS",
  "message": "操作成功",
  "data": {
    "product_id": "product_demo_off_sale",
    "view_status": "OFF_SALE",
    "store": {
      "store_id": "store_demo",
      "name": "演示好物店"
    }
  },
  "request_id": "request_demo_off_sale"
}
```

该状态页下方推荐区按 D058 / D059：优先本店同类近价的在售有货商品，不足再由全站同类补齐，仍不足少展示；排除原商品、下架/受限/停用店铺及无有效有货 SKU 的候选。首页混合新品/人工精选/分类并适当打散店铺，相近候选少量稳定轮换；翻页及详情返回保持顺序，用户明确排序优先。推荐复用公开商品卡片及 D060 展示价，近价匹配对自填值的处理随 P035 细化，不占库存，也不把原 SKU 标为可买。喜好推荐留待有行为数据后；接口路径/输入/输出及参数尚未冻结，本轮未新增可调用 API，见 [数据库讨论 3.8](13-数据库设计.md)。

D066 统一成功/失败 Result<T> 外层 code/message/data/request_id，结果码来自 ResultCode 枚举，成功 SUCCESS，失败 data=null。错误采用相应 HTTP 状态与稳定业务码：参数错误 `400 / INVALID_ARGUMENT`，需要身份的接口未登录 `401 / UNAUTHENTICATED`，无操作权限 `403 / FORBIDDEN`，不可见/不存在 `404 / NOT_FOUND`，结果上下文失效 `409 / FEED_EXPIRED`，超出查询频率 `429 / RATE_LIMITED`，暂不可用 `503 / SERVICE_UNAVAILABLE`。实际限流策略与阈值随工程确定，不在此宣称已实现。

```json
{
  "code": "INVALID_ARGUMENT",
  "message": "最高价格不能低于最低价格。",
  "data": null,
  "request_id": "request_demo_error",
  "field_errors": [],
  "details": null
}
```

订单、地址、开店资料与商家后台不是当前预留的公开导购能力。未来若增加订单查询，必须从已验证身份获取用户上下文并逐次校验归属。当前不提供 Agent 加购、下单、支付、改价、改库存、发货、删除或平台处理能力。

## 5. 后续工程验收清单

以下均为待执行项，不是本轮测试结果：

1. 前端普通搜索与后续可复用 API 使用相同商品、D060 展示价来源、商家主图、店铺状态和分页规则：填写值优先，未填/清空自动回退；自动分支缺货低价不压低有货起价。自填值不改变 SKU 实际售价、库存与结算；自填标签及过滤/排序按 P035 确认后再补验收，不能写为当前已通过。
2. 正常、零库存、下架、平台限制、停用店铺、无结果及非法参数响应与契约一致。
3. SKU 批量查询及时反映价格与库存变化，查询前后库存数量与占用记录不因读取而变化。
4. 返回字段不包含联系人、地址、成员资料、内部成本或审核记录。
5. 记录 OpenAPI、虚构响应示例和可执行检查；API 能独立于模型服务工作，未接入 Agent 不阻塞商城第一版交付。
6. D055 的规格图片归属/主图回退及首次发布时间排序一致；编辑、改价和重新上架不能让同一商品重置上新排序时间。
7. D058 的商家自主下架返回最小状态，搜索不再包含该商品，不能新加购/结算；草稿/平台限制/停用店铺仍按统一不可见响应，不能借状态页公开管理数据。
8. D059 的候选在售有货、报价一致、下架页本店同类近价优先再全站补齐，数量不足少展示；首页相近候选轮换且分页/详情返回稳定，明确排序优先。具体数量、近价阈值和稳定结果集实现随工程细化，当前均为待执行项。
