# 拾集 · 确认收货交付

日期：2026-10-25；基线 5194c2c，D102。沿用 D099 自动提交推送，本轮仅补齐买家模拟确认收货。

## 1. 实现与规则

- 沿用 O03，在已付待收货订单详情提供确认收货。二次确认展示本店商品/规格/数量、金额与物流；默认聚焦“暂不确认”，支持取消、Escape、双向 Tab 循环和返回原入口。
- 当前店铺整笔订单一次完成，同次保存 COMPLETED、首次 received_at、支付单中对应订单摘要及回执。支付保持 PAID，同组其他店铺状态、成交金额/商品/地址/物流快照及已付库存保持。
- 回执绑定当前订单及操作。原键重放只读当前结果；新键遇已完成订单只补回执，不再次完成或覆盖时间；同一键不能换目标/动作。未付款、待发货、取消/超时关闭、缺失订单拒绝收货，读写失败不留下部分状态。
- 读取时派生买家 allowed_actions，旧待收货快照无需迁移即可继续收货；校验已完成订单的收货时间和回执关联，损坏记录拒绝继续写入。
- 收货接入既有全局协调，重复点击合并为一次请求。明确失败后重新核对状态并可再确认；结果未知保存原订单/键，锁住其他交易，可换页确认原操作后回买家详情，保留订单列表条件/页码。
- 成功后详情读取失败保留成功提示，仅重新读取，不再确认收货。正常完成/重读失败后分别聚焦状态标题/重读按钮；买家显示收货时间，商家列表/详情同步完成状态与时间并保持字段白名单。

仍基于虚构买家与同一本机快照，不代表真实账号认证、服务端归属、跨标签并发或数据库事务验收。OpenAPI 0.5.2 的 O03 和既有响应沿用，无新增依赖、接口、自动收货任务、后端或数据库迁移，未改旧 HTML 原型。
