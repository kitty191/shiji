## 2. 六项精修的评审依据（实施前）

| 问题 | 评审时核对的原型情况 | 采纳方向与理由 |
| --- | --- | --- |
| 大屏横向拉伸 | 根容器为 `width:100%`，商城外壳没有整体最大宽度；截图中商品、横幅和搜索明显被拉宽。详情内部已有 `max-width:1380px`，不能说所有页面都没有限制 | 建议商城外壳或统一内容容器约 1280 px 居中，实际值待预览确认；保留已有四列方向、右侧工具栏与收起补齐规则 |
| 筛选区松散 | 分类、价格、当前条件、计数与排序分别输出；价格表单中的空错误区也保留最小高度及上边距 | 建议组成紧凑的筛选区域，计数与排序靠近；有空间时一行，不足时有序换行。空错误区不常驻占位，有错误时在对应控件附近展示 |
| 橙色强调过多 | 已共用一个橙色变量，但搜索、分类、应用价格和选中排序同时使用强强调 | 建议保留主操作实心橙；分类用中性描边或浅底，排序采用轻量选中态，应用价格降低强调。价格保留橙字，不靠增加更多色彩建立层级 |
| 商品标题不能进入详情 | 当前卡片图片有 `data-detail`，标题仅有 tooltip；店铺名进入店铺。标题入口确实缺失 | 建议标题改成可键盘访问的链接或按钮，指向现有商品详情；保留店铺与加购的独立操作，避免整卡覆盖层遮挡它们 |
| 图片留边及暗色背景 | 当前内嵌 9 张主图均为 480 × 480，卡片图片区默认 4:3，使用 `contain`；该图片区暗色背景仍是浅灰 | 建议优先试 1:1 卡片图片区，使现有方图完整呈现；统一图片区背景，暗色使用产品自己的深色表面。未来异形图按内容选择裁切或完整展示，详情仍优先展示完整商品 |
| 商品卡文字层级 | 商品标题字号偏小且预留两行；价格与“起”的字号和基线不统一 | 建议适度拉开标题、价格和店铺来源的层级，把价格与“起”作为统一价格组件处理。保留已确认的最多两行标题和店铺/价格/加购对齐，不直接改成所有标题单行截断 |

## 3. 其他建议与取舍

本节保留讨论依据；焦点已随 D041 增强，其余可选修饰未在本轮整体实施。

| 第三方建议 | 本项目的取舍建议 |
| --- | --- |
| 中文标题取消负字距 | 当前 H2 确有 `-.5px`，开店大标题还有 `-1px`；可以回到 0 作为低成本优化，但负字距不是仅能用于英文，也不能仅凭数值认定为严重缺陷 |
| 字号减少、标题加粗 | 值得在正式前端提炼文字样式，优先治理商品标题、价格、搜索与辅助信息。具体字号和 550/600 字重不是硬性标准；不能把当前仅使用 400/500 等同于没有层级 |
| 间距使用统一体系 | 支持收敛常用间距和圆角变量；不机械删除全部 7、9、13 px。文字行高、边框和图标的视觉对齐仍允许例外 |
| 搜索字号提高 | 建议桌面搜索提高到约 16 px，理由是最常用输入应易读；iOS 聚焦问题不属于本轮桌面范围的验收依据 |
| Hero 增加入口 | 可选“看看最新上架 →”，进入真实上新排序；若没有按日期筛选，不写“今日”。当前没有退款售后，不能为了填充横幅增加“7 天无理由”承诺 |
| 移除购物袋 emoji | 属于低成本视觉整理，可移除或替换为现有图标体系；不必为装饰单独制作复杂插画，也不属于阻塞演示的问题 |
| 图片加标签 | 只显示有依据的标签。包邮沿用既定规则，库存必须对应明确规格，新品需要发布时间或定义；不额外编造销量、折扣或服务承诺 |
| 重置价格改文字操作 | 支持降低其视觉权重；当前本来就在应用按钮右侧。保留明确的字段标签、金额单位及多规格起价筛选规则；原建议将说明移至简洁帮助，后由 D043 确认去掉问号及说明 |
| 加统一焦点样式 | “没有自定义规则”不等于没有焦点指示。D041 已添加产品自己的焦点描边，并在当前暗色外观下实际检查分类入口的键盘焦点；其他外观与全部控件仍需正式前端继续验证 |
| 按钮增加过渡 | 颜色/描边的轻量过渡可后置；不要求所有按钮移动或缩放。若加入动效，应照顾减少动态效果的偏好 |
| 拆分图片区样式 | 正式前端值得按卡片、详情、缩略图明确职责；不同场景采用不同 `object-fit` 本来可能合理。现状确有多层追加规则，但不能仅以同一类名出现多次认定每条都冲突 |

## 4. 无需采用或已由现状解决

| 判断 | 核对结论 |
| --- | --- |
| 为 390 px 手机端增加底部导航 | 不属于首版；D006 已明确仅桌面，不因此新增移动端产品流程 |
| 把搜索移到 Logo、账号同一行 | 与已保留的独立搜索行方向不同，暂不建议。先解决容器过宽；必要时在现有搜索行内限制搜索宽度，不必重做头部 |
| 所有控件统一成 36/44 px 高 | 同类控件应一致，链接和主操作无需尺寸完全相同。D039–D040 已将排序/订单状态统一为 84 × 34 px，购买/资料操作统一为 112 × 40 px；不把截图旧尺寸当成未处理的新问题 |
| 分页永远不出现 | 不成立。`listSize=12`，超过 12 件会出现；既有 13 件数据的第二页和返回/刷新已检查。9 件不显示分页是正常行为；当时结果数量用于反馈筛选，D047 后首页已按用户要求移除，店铺保留 |
| 为显示分页改成每页 6/8 件 | 当前没有必要；不能为了让控件可见而改变已经确定的每页 12 件。评审可用额外种子商品验证分页 |
| 9 件商品最后孤立一张，需推荐位填充 | 普通网格允许末行不满，正式商品数量和筛选结果随时变化；不为凑齐一行新增无业务依据的推荐位。每页 12 件本身已是四列的整数倍 |
| 标题一律单行 | 与已确认最多两行及商品信息表达冲突。可以压缩过大间距、调整店铺来源行，仍保留两行长标题的阅读空间 |
| 演示工具必须重新收起 | 当前已是默认折叠的 `details`，此部分已实现。正式产品不带演示/Tweak 控件；若需更干净的评审版本，再考虑整体隐藏，不能把设计控件当作商城功能 |

## 5. 本轮确认范围与原型结果（D041）

用户明确“按照你说的来改动”，已将 P020 的六项精修及焦点检查落实为 D041。会话原型、工作区源文件和浏览器导出已同步。

| 方向 | 当前原型 |
| --- | --- |
| 大屏限宽 | 根内容最大 1280 px 并居中；2200 px 预览已测得根宽 1280 px，仍为四列 |
| 紧凑筛选 | 首页与店铺共用分类、价格、计数/排序区域；按 D044 将分类与价格放在上方，排序固定在下方独立一行；D047 移除首页总数，店铺仍保留结果数，行内空间不足再换行。空错误区隐藏，错误出现时就近展开；按 D043 去掉问号及配套说明，保留金额单位、字段标签与起价筛选规则 |
| 强调层级 | 搜索/购买保持主操作样式；分类中性描边，排序下划线选中，应用价格普通按钮、重置弱化，价格保留橙字 |
| 方形图片区 | 默认与设计控件初始值改为 1:1；现有方图完整展示，卡片背景使用产品主题表面色，详情不强制裁切 |
| 标题入口 | 店铺先作为来源行，标题采用可键盘访问的按钮进入详情；图片、店铺和加购各自保持原操作 |
| 卡片文字 | 标题 14 px / 21 px 行高，保留两行；价格 22 px，较窄预览 20 px，起价标记 12 px 与金额基线对齐 |
| 焦点 | 产品控件增加 2 px 描边、3 px 间隔；分类入口的键盘焦点已在当前暗色外观观察到 |

保留桌面四列、独立搜索行、右侧工具栏及收起补齐、详情图集、两行标题和每页 12 件。Hero、装饰图、全站字体体系重做、额外标签和动效不在本轮实施；正式前后端、云环境与 Agent 边界继续按既有约定。

本机原型检查包括筛选/排序组合、标题 Enter 进入详情、返回恢复条件、价格错误与重置、店铺共用工具区、工具栏收放和部分宽度回退；具体结果及未验证项见 [原型进度](09-原型进度与文档维护.md)。

## 6. Gemini 界面建议评审（P021，待确认）

| 建议范围 | 当前情况与取舍 |

| 官方/旗舰标签、销量、划线价、倒计时和评价 | 需要认证、成交、有效参考价、活动和评价的对应模型与规则，不能为增加信息密度编造；当前仍不加入。服务文案仅显示当前已定义的演示包邮等规则，不增加未实现的退换货或时效保证 |
| 详情图集、价格区、规格和数量 | 左侧竖排缩略图、中间主图、右侧价格/规格已具备；保留只读数量显示及左右加减。可考虑更清晰的规格选中、售罄和禁用区别，继续允许查看售罄规格并禁止购买，不要求小三角勾或斜线样式 |
| 详情按钮与资料区 | 主次按钮可进一步明确：候选为立即购买实心、加购浅色或描边，继续共用已确认的 112 × 40 px，不自动改成 44 px。已有商品介绍与参数；内容较短时无需额外 Tab，不加入空评价区 |
| 购物车分组与结算栏 | 店铺分组、复选框、规格、数量、小计和删除已具备；完整购物车的结算汇总可考虑在长列表滚动时保持可见，限制在购物车内容范围，避让右侧工具栏，不让所有页面常驻窗口级底栏。批量删除是额外操作范围，暂不顺带添加 |
| 右侧工具栏 | 已有购物车/消息/客服、角标、收放及收起释放占位，保留宽度和文字标签。文字不只在 hover 后可见；用户后来按 D049 确认滚动跟随和约两屏后返回顶部，现已更新原型；收藏仍为额外候选 |

本轮仅做源码和文档核对，没有新增视觉对比图、浏览器验收或正式接口验收；当前原型及浏览器副本保持原样。

| --- | --- |
| 货架卡片悬浮 | 在支持悬浮的精细指针环境中，上移 2 px、220 ms 过渡，增加随浅/暗主题变化的柔和阴影。保持卡片宽高、网格、图片/标题、店铺和加购的独立入口，不增加图片缩放 |
| 核心操作按压 | 仅搜索、卡片加购/选规格、详情加购和立即购买有缩放反馈；非禁用态按下缩至 0.98，按下 80 ms、恢复 160 ms。数量、排序、菜单及复选框不缩放，不做弹跳 |
| 搜索聚焦 | 增加暖橙边框和 3 px 柔光，浅/暗外观分别配色，180 ms 过渡；保留原有 `:focus-visible` 2 px 描边及 3 px 间隔。不采用循环呼吸或闪烁 |
| 减少动态效果 | 取消卡片位移、核心按钮缩放及相关过渡，保留颜色、阴影和清晰焦点状态；该分支已静态核对，本轮未实际切换系统偏好 |

没有更换品牌、布局或按钮尺寸，没有恢复首页商品总数，没有改变排序在筛选下方的规则，也没有新增动画依赖或业务接口。实际动态状态通过同一源片段的临时直接预览副本检查，避免内嵌包装器的输入自动化限制；具体结果与未验证项见 [原型进度](09-原型进度与文档维护.md)。

## 9. 工具栏跟随与返回顶部（D049）

用户明确要求滚动页面时仍能打开工具栏，并在下滚约两个浏览器窗口高度后提供一键回顶。当前原型在首页、店铺与详情共享实现：首屏保留下移方向，空间不足时避让窗口边界；深滚动后工具栏约距可见窗口顶部 24 px，把手同样跟随，面板限高并可内部滚动。收起继续释放商品区占位。

回顶按钮在累计滚动达到 2 倍当前窗口高度后出现，独立于工具栏收放；点击平滑回到页首后隐藏，减少动态效果时直接回顶。该变更替换“仅按正文固定偏移”的旧行为，顶栏仍随文档滚动，每页 12 件及后续滚动续载边界不变。

独立浏览器包装页同步外层可见范围，以适配自动增高 iframe；跟随位置不会用于持续增加正文最小高度。已执行的原型检查及未验证环境见 [原型进度](09-原型进度与文档维护.md)。

## 10. 参考资料

- [W3C：Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)：关注键盘焦点是否清晰可见，默认平台指示与自定义指示均可作为实现途径；不能只数 CSS 规则。
- [MDN：object-fit](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/object-fit)：`contain` 在比例不同时可能留边，`cover` 可能裁切；需要根据实际商品图片选择。
