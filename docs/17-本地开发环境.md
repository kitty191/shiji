## 2. 现有程序、镜像和登录的区别

- Mac 上安装的 MySQL / Redis 是宿主机程序，可以直接使用，无需 Docker 镜像；它们不会自动变成 Linux 容器。
- 已下载的 Maven/JDK 21 与 Node 24 镜像可以继续复用。当前 [compose.yaml](../compose.yaml) 只保留 tools profile，固定已验证摘要，并设 pull_policy: never；本地缺失时失败，不自动联网下载。
- 若以后明确要求将数据库容器化，再评估已有对应镜像及数据迁移；不是当前必须步骤。
- Docker Hub 的公开镜像允许匿名拉取，登录不是公开镜像下载的前提；匿名有额度限制，私有仓库需要相应访问权限。[Docker 官方说明](https://docs.docker.com/docker-hub/usage/pulls/)

Docker 登录与本机下载/执行权限是两件事。D071 镜像下载请求未获批准，当时没有下载 MySQL / Redis；D072 不再继续该请求，也不尝试其他路径下载。

2026-10-23 用户进一步明确直接使用本机现有 MySQL / Redis，并询问能否放进 Docker。现有 macOS 安装不会直接变成 Linux 容器；当前继续在 Mac 运行数据库，不迁移数据或下载第二套数据库镜像。

若后续 Java 运行在 Docker Desktop 容器中，可以按官方方式通过 host.docker.internal 访问 Mac 服务：MySQL 候选地址为 host.docker.internal:3306，Redis 为 host.docker.internal:6379。容器自己的 localhost 不代表 Mac。此为后续接入方式说明，尚未配置或验证监听、认证与访问权限，不因此修改数据库监听或开放外网。[Docker Desktop 官方网络说明](https://docs.docker.com/desktop/features/networking/networking-how-tos/)
