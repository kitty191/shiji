# 拾集 · 模拟发货交付

日期：2026-10-25；基线 041db4b，D101。沿用 D099 自动提交推送，本轮仅补齐模拟发货，确认收货另批。

## 1. 实现与规则

- 沿用 F03，在已付款、待发货的本店订单详情提供物流公司/运单号表单。必填、去首尾空白、拒绝控制字符；不限定承运商列表或运单格式，不发起实际寄件。
- 发货整笔本店订单，一次快照写入 PENDING_RECEIPT、原物流/首次发货时间、对应支付单摘要及回执；同组他店订单和 PAID 状态保持，成交/地址/金额快照保持，不二次扣库存。
- 回执绑定店铺、订单和规范化物流请求。原键重放只恢复结果；新键且内容相同只补回执、不重发；不同物流不可覆盖。重新校验当前店铺归属，无权限或他店/缺失订单拒绝，未付款/取消/超时订单不能发货。
- 扩展现有交易协调为 ship；同时点击合并请求，未确认发货锁住其他交易。明确失败保留输入并允许编辑后重试；未知响应关闭编辑、保留原目标/运单/键，可站内换页确认原发货；恢复回本店详情并保留列表条件。
- 未保存输入在取消/Escape/站内离开前有丢弃提示，页面刷新/关闭也有提示；提交期间禁止放弃。连续明确失败后焦点回确认按钮，输入变更清除已过时的本地错误；发现订单已发货或权限变化时只允许返回重读。
- 已成功但详情读取失败保留成功提示，重试只读不再发货。买家详情增加发货时间；订单/支付单两次读取之间发生发货时，即使支付状态仍 PAID，也会重读完整订单以保留正确物流。

仍基于虚构商家上下文与同一本机快照。OpenAPI 0.5.2 的 F03/ShipRequest 沿用，未新增接口、依赖、真实物流、后端或数据库迁移，未改旧 HTML 原型。
