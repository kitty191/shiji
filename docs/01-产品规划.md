# 拾集 · 产品规划 v0.3

更新日期：2026-10-20  
状态：当前桌面原型与功能范围已暂定为第一版基线；正式工程尚未接入。未确认的技术与扩展建议仍单独标注。

## 1. 产品定位

拾集是一个参考淘宝业务结构的多商家商城，围绕“商家开店卖货、买家发现商品并购买、平台管理交易”建立完整流程。Agent 作为后续扩展方向保留。

项目首先服务于全栈实战作品展示，并为后续 Agent 实战保留业务基础。首版的价值在于：界面可用、交易规则完整、角色权限正确，商品查询接口可复用。

2026-10-18 用户确认当前原型和功能范围先定为第一版，后续按新增需求增补；Agent 暂不开发，仅预留商城查询 API 契约及权限边界，见 [Agent 接口预留](11-Agent接口预留.md)。不创建 Agent 服务、模型调用、对话入口或运行记录。正式前后端与这些查询 API 均待工程接入后实现。

品牌表达建议采用“淘到实惠好物”的轻松风格。商品是否聚焦尾货、低价商品或其他垂直品类仍待确认；产品不预设为废品回收或个人闲置交易。

参考淘宝的信息组织与购物流程，使用自己的品牌、页面布局、素材与演示数据。暂不要求复刻淘宝全部功能或页面细节。

## 2. 用户与任务

| 角色 | 核心任务 | 成功标志 |
| --- | --- | --- |
| 买家 | 找到合适商品、选择规格、购买、跟进订单 | 从搜索、分类或列表进入商品，完成购买与收货 |
| 商家 | 入驻、维护商品和库存、处理本店订单 | 商品在商城展示，本店订单能发货并完成 |
| 平台管理员 | 审批入驻、管理分类与商品、查看交易 | 能管理平台，并识别订单与店铺归属 |

一个账号可以有多个角色。商家权限还必须绑定具体店铺；拥有“商家”角色并不代表可以访问所有店铺。

按 D051，首版一个账号最多拥有一家店，账号、店铺与成员关系保持独立，为以后扩展保留结构。当前不开放多店切换或员工管理；停用店铺继续保留归属，不能通过停用绕过开店上限。数据库约束与候选字段见 [数据库讨论稿](13-数据库设计.md)。

普通用户共用注册登录入口，默认进入买家商城；头像菜单统一使用“商家中心”。没有开店申请时先展示开店权益、准备资料、流程与常见问题，用户点击“免费开店”后才进入申请。已有草稿、待审核、驳回或已开店状态分别进入续填、进度、修改或工作台。管理员权限由受控流程分配。

按 D052，直接访问平台管理入口时，未登录则进入共用登录页，认证后由后端检查管理员角色，有权限再进入管理台；已有有效登录态直接校验权限。普通登录默认进买家首页的规则不变，不新增另一套管理端登录或公开管理员注册。

| 模块 | P0：完整演示版 | P1：增强版 |
| --- | --- | --- |

| 接口预留 | 约定商品搜索、详情、SKU 价格库存、公开店铺与分类查询接口；随 Java 商城实现，不开发 Agent | 用户后续启用后，再评估只读导购、上架助手及规则客服 |

第一轮不纳入秒杀、直播、分销、多仓、跨店优惠分摊、平台抽佣和商家资金结算。P0 不提供已支付取消、退款与售后能力，相应入口不展示为可用功能。

正式工程需由商城数据库保存演示业务数据；支付与物流使用模拟能力，页面明确标注。当前原型仅使用本地模拟数据，未接入数据库。

## 4. 页面结构

### 买家商城

- 首页：左上独立品牌区、右上头像昵称、下一行搜索、分类下拉列表和商品流；分类入口沿用当前界面的配色、描边与圆角。购物车、消息、客服集中到右侧可收放工具栏，工具栏、把手及面板随滚动保持可达。下滚达到约两个窗口高度后显示独立返回顶部，收起工具栏后仍可使用；收起后商品与横幅自动补齐右侧空间。推荐按 D059 在现有商品流混合新品、人工精选和不同分类，适当打散店铺，相近候选少量稳定轮换。
- 商品列表：关键词、分类、价格区间、店铺结果数、价格/上新排序、当前条件与空结果；原型已加入每页 12 件分页，少于一页时隐藏分页操作。筛选改变回到第一页，从详情返回保留条件与原页。价格区间原按自动起价匹配，D060 自填展示价分支的过滤/排序见 P035 待确认；正式工程仍需服务端分页和报价。
- 商品卡片：主图默认 1:1，店铺作为来源行，标题可点击进入详情且最多两行，价格、起价标记与加购对齐；常用桌面宽度每行四件商品，较窄窗口保留三列，断点按商品可用宽度处理。
- 商品详情：最左侧竖排缩略图栏，中间主图，右侧标题、店铺、分类、所选 SKU 价格/库存、数量与加购/立即购买；数量仅用左右「− / +」调整，中间只读且无上下箭头；下方商品资料，店铺名进入本店商品页。
- 店铺页：店铺资料、本店搜索/分类/价格条件和排序，与全站搜索明确区分。
- 桌面内容：最大 1280 px 居中；分类与价格同组，排序固定在下方独立一行；按 D047 首页不显示商品总数，店铺保留本店结果数。行内空间不足时有序换行（D044）。分类中性描边、排序下划线选中，主购买/搜索操作保留强强调；价格筛选不再提供问号说明入口，保留金额单位和字段标签，空错误区不常驻占位。
- 购物车：店铺分组、单件/整店/全选、改数量、选中金额；删除后 8 秒内可撤销最近一次删除，完整页明确下架、售罄与库存不足，异常商品不参与结算。
- 商家下架状态页（D058）：购物车提示“商品已下架”，点击后进入下架状态页，上方提示已下架，下方按 D059 展示同类近价的在售有货商品；不展示为仍可购买的详情。不能把规格替换失效进原店铺的 D057 路线用于整款下架。
- 右侧工具面板：购物车摘要、订单/系统/入驻状态消息、帮助与问题反馈；同一时间只展开一个面板。消息不等于即时聊天，客服先提供帮助与反馈。
- 结算页：地址、各店商品、费用明细、提交订单。
- 支付结果页：本次支付结果、店铺订单入口。
- 个人中心：地址、订单列表、订单详情、确认收货；订单清楚标识店铺、状态和下一步。
- 导购面板（后续候选，当前不开发）：以后启用 Agent 时再讨论悬浮球、对话和商品卡片，不属于首版页面范围。

### 商家工作台

- 商家中心：未开店先展示权益、流程与常见问题；确认开店后填写申请，按状态展示草稿、审核进度、驳回原因或已开店工作台；进度中包含提交时间与审核历史。
- 工作台概览：新店先引导发布第一件商品；有商品后展示在售商品、待发货与低库存等经营待办，指标取实际数据。
- 店铺资料。
- 商品列表与商品编辑：带名称/状态筛选的表格；图片、介绍、草稿、预览、多规格价格/库存、发布、编辑及单件/批量上下架。批量逐件校验并显示成功和未处理原因；原型为本地模拟，图片库选择可用，正式上传待接入。
- 订单列表与详情：带订单号/商品及状态筛选的表格，只展示本店明细，填写演示物流并发货。

### 平台管理台

- 入驻审核。
- 分类管理。
- 店铺与商品管理。
- 订单查询与基础交易统计。
- Agent 运行记录（后续候选，当前不开发）：以后启用 Agent 时再设计，不属于首版管理菜单。

首版只考虑桌面端，采用一个 Web 前端工程，按商城、商家、平台管理分路由与布局。手机端设计和移动适配不属于当前范围。

## 5. 跨店交易规则

### 5.1 商品与规格

SPU 表示一款商品，SKU 表示可购买的具体规格组合。价格、可售库存均落在 SKU；无规格商品也有一个默认 SKU。首版支持最多两个规格维度，例如颜色和尺寸。

D081：无明确规格上下文时，按返回 SKU 顺序自动选择第一个有货的完整规格，展示实际价和库存；全售罄时不伪造有货选择。有明确选择时保留并核验，失效时提示重新选择，不自动改绑。
按 D053，商品属于店铺，同型号跨店售卖各有商品记录；SKU 属于商品，库存关联 SKU。购物车商品项与订单明细引用具体 SKU，成交信息保存快照，金额按整数分存储；后续字段、接口和权限校验遵守这些归属。规格维度/值/组合的具体拆表仍在 [数据库讨论稿](13-数据库设计.md) 中评审。

D060 更新 D054：商品主图仍由商家指定为图集首图；商家可选填展示价，填写时优先展示，未填或清空时自动取商品 SKU 最低价，自动分支继续沿用有效启用且有货优先范围。全部售罄仍明确售罄并禁购，无有效 SKU 不进入正常货架，自填价不能改变可售状态。详情所选 SKU、购物车及结算仍按实际 SKU 售价。P035 待确认自填标签、校验范围及价格筛选/排序，建议统一使用最终展示价但尚未采纳。本轮仅设计同步，未改 Demo 或后端。

商家调整库存只能调整可售数量，不能覆盖已占用库存；调整与交易采用同一并发控制规则。商品或 SKU 关联历史订单后保留记录，使用下架或停用代替物理删除。

D055 确认商品草稿允许未填完整；保存成功后持久化已有文本、图片及顺序、已填写的规格和价格/库存，再次进入同一草稿时回显并继续补充。重复保存更新同一个商品，不重复建商品；未保存输入不承诺跨刷新/关闭恢复，当前运行页面 401 内存保护按 D062。正式发布至少具备有效分类、标题、主图和有效 SKU，具体字段限制继续细化。

D055 同时确认 SKU 可选绑定一张本商品图片，未绑定或失效时使用商品主图；库存人工调整保存前后数量、原因、操作者和时间，并防止旧编辑表单覆盖新库存；“最新上架”按首次成功发布时间排序，修改内容/价格和重新上架不重置。D057 确认替换旧组合时保留并停用旧 SKU，为新组合创建新 SKU，一次保存完成；旧购物车保留原选择、显示“所选商品不能购买”，商品缩略图/图标变灰，不可勾选结算，点击图片或标题进入原店铺，不自动换成新规格。库存为零仍按已售罄表达，与规格停用分别处理；具体字段继续细化；详情默认选择按 D081。上述是设计目标，本轮未改 Demo、数据库或实际接口。

D062 已确认退役组合再次销售创建新 SKU ID，旧 SKU 保持停用；只限制同商品同时启用的完整组合唯一，历史可多代保留同组合，旧购物车不自动恢复或改绑。临时断货仍按库存为零处理。同期确认购物车连点按项串行/合并目标、素材无引用核查回收及 401 当前内存输入保护；规则见 [接口文档第 19 节](16-接口文档.md#19-d062-本轮确认与验收准备)。这些是待实现行为，不扩展为未保存输入跨刷新恢复，不新增真实退款/自动收货/Agent。

#### 商品下架与推荐范围

D058 确认商家自主下架后保留商品记录和历史订单，购物车不能勾选结算，点击进入下架状态页并在下方展示其他商品推荐。仅在原商品曾公开、店铺正常且无平台限制时提供最小下架状态；草稿、平台限制、停用店铺继续按原可见性规则。已有未过期待付款单沿用既有支付规则，下架不等于取消历史订单。

P032 已由 D059 采纳。首版首页在现有商品流混合新品、人工精选和不同分类，适当打散店铺，相近候选少量稳定轮换；下架页优先本店同类、价格接近的可买商品，不足再由全站同类补齐，仍不足则少展示。候选来自正常店铺的在售、无平台限制且有有效有货 SKU 的商品，排除原下架商品，卡片报价按 D060，近价匹配对自填值的处理随 P035 细化；翻页与详情返回保持顺序，用户明确的排序优先，每页 12 件不变。喜好推荐留待行为数据积累后，当前不新增喜好表或行为采集。具体参数及接口字段继续细化，详见 [数据库讨论 3.8](13-数据库设计.md)；本轮未改 Demo、数据库或实际 API。

### 5.2 一次结算怎样拆单

买家从 A 店和 B 店各买一件商品，一次结算生成一个支付单和两个店铺订单。支付单管理统一付款，各店铺订单分别发货与完成。

首版统一采用人民币、整数分计价、包邮，不引入优惠。应付金额为各 SKU 成交单价乘以数量的总和，全部由后端计算。

同一支付单中的订单使用同一地址。提交订单时冻结商品名称、规格、图片、成交单价、数量、费用与收货地址，后续修改商品或地址不改变历史订单。

### 5.3 付款与取消

- 结算预览不占库存；提交订单时重新校验价格、商品状态、店铺状态和库存。
- 价格与预览不一致时，返回新报价，由买家重新确认，不直接按更高价格提交。
- 提交订单成功后占用库存；建议有效期为 15 分钟，由服务端生成截止时间。
- 首版整次结算统一付款；待付款时只支持取消整次结算，关闭所有关联店铺订单并释放库存。
- 模拟支付失败可在截止时间前重试；超时或主动取消后不可再次支付。
- 支付成功后，各店铺订单独立履约。首版不处理已支付取消、部分退款或部分付款。
- 重复点击提交、重复支付通知、重复取消不能产生重复订单或重复库存变动。

### 5.4 状态定义

| 对象 | 状态与转换 |
| --- | --- |
| 入驻申请 | 草稿 → 待审核 → 通过 / 驳回；驳回后可修改并重新提交；未申请时仅展示开店介绍 |
| 店铺 | 正常 / 停用 |
| 商品 | 草稿 → 在售 → 下架；下架商品可编辑后重新上架 |
| 支付单 | 待支付 → 已支付 / 已关闭 |
| 店铺订单 | 待支付 → 待发货 → 待收货 → 已完成；待支付可变为已关闭 |

支付单没有“统一发货”状态，避免两家店铺履约进度不同而产生歧义。
商家自主下架的商品可重新上架；平台限制售卖的商品保留限制原因，平台解除前商家不能通过普通上架操作绕过。
停用店铺或下架商品禁止新结算；已生成的待支付单仍可在截止时间前付款，已有订单仍可按权限查看和履约。卖家不得直接修改已售订单金额。

## 6. 后续 Agent 产品方案（暂缓）

本节保留后续讨论材料，不属于当前开发或首版验收。依据 D037，重新启动 Agent 开发需用户后续要求；当前只维护 [查询 API 契约](11-Agent接口预留.md)。

### 后续候选：买家只读导购

示例需求：“200 元以内，办公室用，想要安静一点的无线键盘，帮我比较几个。”

流程：识别预算与用途 → 必要时澄清关键条件 → 查询商城商品 → 读取候选规格与最新价格库存 → 返回 2–4 个候选及比较 → 买家点击商品卡片进入详情和常规结算。

如果商品没有噪声等客观参数，应标注“资料未提供”，不能凭空保证性能。无匹配商品时说明限制，提出调整预算或筛选条件的建议。

结果要求：每个候选都来自商品接口；卡片有有效商品链接、具体 SKU、店铺、查询时的价格与可售情况；推荐理由能对应商品事实。最终下单以服务端结算校验为准。

后续第一阶段导购建议只使用只读商品工具。用户通过普通页面加购和结算，便于验证导购质量与完整交易流程。

### 后续增强候选：商家上架助手

商家提供商品事实、规格与卖点 → 生成标题、描述、分类建议和属性草稿 → 表单展示草稿差异 → 商家编辑并保存 → 使用普通发布流程上架。

未知的品牌、性能、价格和库存保留为空或要求补充。自动保存草稿必须限制在当前店铺；正式发布由商家确认。

### 更后续候选：规则与订单客服

平台规则可通过带来源的文档检索回答；订单进度通过当前用户授权的查询工具获取。是否加入退货申请工具，在售后业务实现后再评估。

## 7. 作品完成的判断

- 能从商家入驻审批走到商品发布，再由买家完成跨店购买和分别收货。
- 页面具备加载、空数据、失败、无权限、库存不足和价格变化等状态。
- 切换账号后数据归属正确；历史订单信息稳定。
- 商品查询接口具有明确字段、金额单位、可见范围、分页与错误约定，并通过正式工程的接口验收；Agent 接入不作为首版完成条件。
- 有固定种子数据、演示账号、启动说明与演示脚本，可以重复展示。
- 功能是否完成以可执行验收为准；本文件不表示功能已实现。
