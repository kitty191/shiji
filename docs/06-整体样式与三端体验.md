# 拾集 · 整体样式与三端体验讨论稿

更新日期：2026-10-20  
状态：当前桌面原型和功能范围已暂定为第一版基线（D036），后续按用户新要求增补；Agent 暂不开发，仅预留 API 契约（D037）。正式前后端尚未接入。

## 1. 整体形态

一个品牌下包含三套使用界面：买家商城、商家工作台、平台管理台。Agent 作为后续候选保留，当前不加入页面流程。

| 界面 | 使用者此刻最关心什么 | 主要形态 |
| --- | --- | --- |
| 买家商城 | 找到想买的商品、比较、付款、跟进订单 | 搜索、分类、商品卡片、详情与购物流程 |
| 商家工作台 | 商品能否售卖、哪些订单待发货、库存是否足够 | 左导航、待办、数据概览、列表与编辑表单 |
| 平台管理台 | 谁申请开店、哪些商品或店铺要处理、交易能否追踪 | 审核列表、筛选、详情、处理原因和操作记录 |

三端共享品牌、字体、按钮、弹窗和状态样式，页面组织根据任务不同。买家强调商品与购买，后台强调信息密度与处理效率。当前保留买家商品流、商家与平台左导航布局，增量补齐登录、昵称头像及账号体验。

已确定商城先使用 Java / Spring，后续再迁移 Python。这不影响当前讨论的页面和体验设计；前端技术、具体配色与细节仍可调整。

## 2. 品牌与视觉方向

建议主线为“淘到实惠好物”：名字轻松、有记忆点，商品与交易信息保持清楚可信。商品暂按普通多商家商品设计；二手、尾货、瑕疵品等属性仅在定位或商品事实支持时出现。

推荐方向：暖橙品牌色、奶白或浅灰底色、深色正文，少量绿色或蓝绿色用于 Agent 标记及成功反馈。用户也可以选择更接近传统商城的高密度样式，或更有个性的潮流捡漏风格；当前先展示清爽商城方向。

具体建议：

- Logo 先以“拾集”中文字标为主，可配自有简洁图形，避免直接使用淘宝图标和品牌素材。
- 宣传语候选：“淘点好物，少花点钱”。它是品牌建议，不表示所有商品都低于其他平台。
- 搜索、价格、购买主操作使用品牌强调色，正文与大面积后台保持中性。
- 商品图片统一比例；主图背景尽量干净，卡片圆角与间距统一。
- 页面有留白，也保留足够商品密度；当前常用桌面宽度每行四件商品，较窄桌面三列。
- 首页主活动区保持一张明确主题内容，后续有真实运营活动再增加广告位。
- 包邮、折扣、销量、品牌认证等标签均有数据依据。首版按既定建议全场包邮，不虚构原价、成交量、评价或商家认证。

按 D048 已补三项微交互：货架卡片在精细指针悬浮时上移 2 px 并加柔和阴影；搜索、卡片加购/选规格及详情购买按钮按下缩至 0.98，排除禁用态；搜索聚焦显示随主题变化的暖橙柔光，同时保留清晰键盘描边。数量、排序和菜单不缩放，减少动态效果时取消位移/缩放，现有布局、尺寸、点击入口与首页总数隐藏规则保持。

视觉比例与尺寸均是设计起点，原型评审后再确定，不作为前端像素级规范。

用户认可轻透毛玻璃材质（D045），并已按 D046 授权更新本地原型：顶栏、右侧工具栏及把手、头像/分类菜单和抽屉外壳使用适配浅/暗外观的半透明磨砂、细边框和柔和阴影，抽屉商品、金额及表单正文维持实底。现有暖橙、布局、按钮尺寸、工具栏位置、筛选上下顺序和收放补齐规则继续生效；顶栏仍随页面滚动，未加入吸顶穿透。增加短暂颜色/描边过渡、菜单和抽屉进入及详情图片切换淡化；不支持模糊时回退实底，并照顾减少动态效果与减少透明度的系统偏好。实际原型检查范围见 [原型进度](09-原型进度与文档维护.md)。

## 3. 入口与导航

### 买家端

桌面顶部第一行：左上角单独展示 Logo 与品牌名；右上角为头像、昵称与账号菜单，访客显示登录和注册入口。购物车移到右侧工具栏，空出头像左侧位置。搜索框单独放在下一行；我的订单从账号菜单进入。首页分类使用与整体界面同质感的下拉列表。

移除顶栏的“AI 导购”按钮，当前示意暂不增加新的导购入口。后续导购入口采用页面右下角悬浮球，点击展开对话面板，收起后恢复小球；不占用顶栏与搜索区域，不遮挡主要购买操作，也不自动弹出。账号菜单统一使用“商家中心”，不随状态改成不同入口名称；进入后的内容由申请及店铺状态决定。平台管理入口只向对应身份展示。

### 右侧工具栏

- 默认展示窄栏：购物车、消息、客服和收起按钮；图标保留文字标签和有依据的角标。
- 按 D049，首页、店铺及详情的工具栏、收起把手与展开面板随滚动保持可达。首屏仍沿用下移方向：工具栏/面板距正文顶部 180 px，把手为 200 px；窗口较矮时优先保证工具可见。往下滚动后，工具栏约停留在窗口顶部下方 24 px，把手额外下移 20 px，并限制在商城正文范围内。顶栏仍随文档滚动。
- 点击条目向左展开相应面板，同一时间只展开一个；购物车提供商品、规格、数量、小计、完整购物车和结算入口。
- 面板跟随工具栏顶部，按当前可见高度限高；内容超出时在面板内滚动，不能因为跟随位置变化持续撑高页面。浏览器包装页同步实际窗口可见范围，避免把自动增高的 iframe 高度当作浏览器窗口高度。
- 消息先展示订单、系统与开店审核通知；客服先提供常见问题和反馈，不承诺已经实现即时聊天或人工在线服务。
- 收起整栏后，只留下贴右侧边缘的小把手；同时撤销整栏的右侧预留空间，使横幅、分类和商品卡片向右补齐，仅留小把手需要的避让，避免遮挡商品。再次展开时恢复间距，不能只隐藏按钮而保留空列。
- 工具栏收起状态恢复或切换分类时，商品区域仍按当前可用宽度排布。展开的面板和未来 AI 悬浮球需要协调位置。
- 下滚达到当前窗口高度的两倍后，在右侧靠下显示独立“返回顶部”，收起工具栏后仍保留；未达到阈值或回到顶部时隐藏。点击平滑回到页首，系统要求减少动态效果时直接回顶；短页面无需强行显示。继续保留每页 12 件，滚动续载仍未实施。

访客可以浏览、搜索和看详情。加入购物车、下单、查看个人数据和使用有会话记录的导购时要求登录，完成后返回原操作上下文。首版不增加复杂的访客购物车合并。

### 商家与平台端

顶部显示当前身份、店铺名称或平台名称、返回商城与头像昵称账号菜单；左侧固定栏目；右侧主内容区。店铺 Logo 与个人头像分别展示，当前栏目、页面标题和主要操作位置保持稳定。

示意中的三端切换仅用于讲解设计，正式产品的入口和操作受登录权限约束。

“平台管理有独立入口”描述的是目标页面与权限。D052 已确认未登录访问管理入口时跳到共用登录页，输入账号密码后由后端核对管理员角色再进入；已有登录态直接检查权限，无权限则拒绝。商家继续从头像菜单进入并复用登录态。无需因此再制作整套登录或另开工程，具体流程见 [登录与账号细节](07-登录与账号细节.md)。当前只确认流程，不改 Demo。

## 4. 买家端逐页设计

### 4.1 首页：开始找商品

建议从上到下为：

1. 顶部左侧独立品牌区，右侧为账号头像与昵称，下一行是明显的搜索框；购物车从右侧工具栏进入。
2. 分类导航。
3. 首屏内容：主题横幅、分类下拉入口和商品流，右侧为可收放工具栏；导购后续统一从悬浮球进入。额外账户摘要、分类侧栏作为后续候选，不替换已保留的当前布局。
4. 精选好物：固定规则或人工选品，展示真实商品。
5. 店铺发现：店铺名称、主营分类和代表商品。
6. 继续逛商品区：分类分组或分页商品流。
7. 页脚：关于、平台规则、帮助和演示说明。

登录前顶栏引导登录；登录后的订单状态数量如需展示，应从真实接口读取，并能进入对应列表。当前原型不额外增加占用首屏的账户摘要卡片。
首版不使用“猜你喜欢”暗示已存在个性化推荐；按 D059 采用规则推荐、人工精选和相近候选的少量稳定轮换。

P032 已按 D059 采纳：在现有商品流混合新品、人工精选和不同分类，适当打散店铺，相近候选少量稳定轮换。翻页和详情返回保持顺序，明确价格/上新排序优先；后续有真实交互数据再做喜好推荐。具体参数仍待工程细化，见 [数据库讨论 3.8](13-数据库设计.md)，不新增首页楼层或个性化入口，本轮未改 Demo。

商品卡片显示主图、两行以内标题、价格、店铺和少量必要标签；价格区间明确标“起”，详情页按所选规格显示成交单价。点击图片或标题进入详情，首版不在列表直接跳过规格选择。

展示数据按 D060 更新 D054：主图仍由商家指定为图集首图；商家可选填展示价，填写优先、未填/清空自动采用有货优先的 SKU 最低价。自动分支同价直接显示、异价标“起”，全售罄明确状态且禁购；自填分支标签、校验及筛选排序见 P035 待确认，不默认把自填价称作最低价。详情选定规格、购物车和结算按实际 SKU 计费。SKU 图片按 D055 可选绑定并回退主图；详情默认选择已由 D081 确认。仅同步设计及契约，未改原型或执行浏览器回归，详见 [数据库设计 3.6](13-数据库设计.md)。

当前按 D041 采用 1280 px 最大内容宽度居中；默认 1:1 商品图区完整展示现有方图，背景沿用浅/暗主题的商品表面色。卡片先显示店铺来源，再显示可点击的两行标题与价格操作；标题 14 px、价格 22 px，较窄预览价格 20 px，“起”使用 12 px 辅助文字对齐。图片、标题均进入详情，店铺和加购保持独立。

### 4.2 搜索与分类：缩小范围

保留搜索词；首页分类收纳为单个下拉入口，默认“全部分类”，选定后显示对应分类名。弹层沿用页面的表面色、描边、圆角和阴影，选中项使用暖橙提示及勾选标识；选择后自动收起，点击外部或按 Escape 收起。支持方向键移动与 Enter 选择，关闭后可回到入口。

当前条件在结果区上方可见，并能逐项移除；分类选择与关键词、价格区间、排序组合生效，从详情返回保留原条件与页码。当前原型已加入每页 12 件分页；服务端分页与参数校验待正式工程实现。用户提出首页后续采用向下滚动继续加载的方向；D047 本轮仅删除首页总数展示，加载批次、触发和结束状态尚未展开，当前分页行为不变。

排序先做综合、价格、上新。未建设真实销量统计前不提供销量排序。结果页明确空结果，允许修改或清除条件重新搜索；加载失败提供重试，不能伪装成没有商品。

正式上新排序按 D055 使用首次成功发布时间；修改标题/价格或重新上架不重置。当前原型尚未按本轮新增规则调整或回归。

排序按钮「综合 / 价格 ↑ / 价格 ↓ / 最新上架」统一宽高、文字居中；当前原型为 84 × 34 px，首页和店铺页共用。空间不足时按完整按钮换行，不因文字长度改变各项大小。

D041 将分类、价格和结果计数/排序集中到共用工具区；D044 按用户要求固定为上下两组：分类与价格在上，排序在下，不因删除说明或窗口变宽而并到上一行。按 D047 首页不显示商品总数，店铺页保留本店结果数。行内空间不足时有序换行。分类改中性描边，排序采用文字与下划线选中，保留上述点击范围；价格应用为普通按钮，重置降低强调。价格字段保留元的单位和读屏标签；按 D043 去掉筛选末尾的问号及配套说明，不另增解释入口。空错误区隐藏，非法价格时就近展示，原有起价筛选规则不变。

### 4.3 商品详情：完成购买判断

桌面端最左侧为竖排缩略图栏，中间为主图，右侧为商品名称、分类、价格、店铺、规格、库存、数量和购买按钮；下方是商品说明、参数与配送规则。以 D035 的参考布局为准。

- 选择不同规格后，价格、库存与可售状态同步变化；图片按实际图集切换，当前演示未按每种颜色另做图片。
- 未选完整规格时，提示具体缺哪一项。
- 购买数量采用左右「− / +」按钮，中间只读显示当前数量，不提供上下箭头；最少 1 件，上限取 99 与当前规格库存中的较小值，售罄时禁用购买。
- 售罄规格明确标记，选中后禁用购买并提示换规格；商品下架时禁用购买操作。
- “加入购物车”用于继续逛，“立即购买”进入相同的结算规则。
- 两个购买按钮等宽等高、文字居中；当前原型共用 112 × 40 px。
- 店铺名称能进入店铺页，不把多商家商品都呈现为平台自营。
- P0 不展示虚构的评价区、优惠券、售后承诺或无法兑现的客服入口。

详情操作区与价格、规格放在同一区域，导购和浮层不能遮挡主要购买信息。

D055 确认的正式工程目标：SKU 可选关联一张本商品图片，切换规格时使用其绑定图，未绑定或引用失效时回退商品主图；列表主图仍由商家独立指定。D081：无明确规格上下文时，按返回 SKU 顺序自动选择第一个有货的完整规格，展示实际价和库存；全售罄时不伪造有货选择。有明确选择时保留并核验，失效时提示重新选择，不自动改绑。当前 Demo 没有按本轮规则制作规格图或调整选择行为。

D058 确认商家自主下架商品的详情状态：点击购物车中的“商品已下架”项，进入下架状态页，上方展示“商品已下架”，下方按 D059 优先本店同类近价的在售有货商品，不足再全站补齐。该页不保留原商品购买操作，也不套用 D057 的直接进原店铺路径。仅针对曾公开、店铺正常且无平台限制的自主下架商品，其他不可见状态遵守原规则。具体推荐参数待细化，本轮未改 Demo。

### 4.4 店铺页：认识卖家

显示店铺名称、Logo、简介、主营分类与在售商品。首版只有固定模板，不做店铺装修编辑器。
提供本店商品搜索或分类过滤，清楚标注筛选范围。没有实际评分机制时不展示星级和信用等级。

### 4.5 购物车：整理要买的东西

按店铺分组，每行显示商品、已选规格、当前单价、数量、小计、删除；底部显示选中数量与合计，支持按店和全选。

缺货、下架、店铺停用和价格变化明确标记。购物车中的报价只作参考，结算再次确认。首版不做“再买多少钱凑优惠”等复杂促销信息。

按 D057，库存为零显示“已售罄”；商家替换规格后，原购物车商品显示“所选商品不能购买”，商品缩略图/图标变灰，不可勾选结算。失效商品的图片和标题保留点击入口，跳转原店铺，不自动改为新规格或进入旧规格购买页；原店铺仍遵守可见性规则。该行为为设计已确认，当前 Demo 未按本轮变更调整或回归。

D058 补充整款商品下架：购物车显示“商品已下架”，禁用勾选结算，点击进入下架提示及其他商品推荐页；区别于库存为零的已售罄及规格被替换的灰图/原店铺跳转。推荐按 D059 同类近价、本店优先再全站补齐，排除原商品及不可买候选，数量不足少展示；策略已确认，具体参数待工程细化。

### 4.6 结算：确认地址、商品与金额

页面减少无关导航，依次显示地址、按店分组的商品、包邮说明、金额与提交操作，右侧显示金额摘要。

提交前明确提示“本次购买涉及两家店铺，将生成两个店铺订单，统一付款”。价格变化时重新显示报价和确认操作，不能静默按新价格成交。

### 4.7 付款与结果：明确当前结果

支付页显示支付单、金额、截止时间与“模拟支付”标记，提供模拟成功操作；接口失败时允许有效期内重试。
成功页展示“已付款”，列出各店铺订单并可查看详情。取消入口表达为“取消本次合并结算”，在确认弹窗中列明将一起关闭的店铺订单。

首版待付款有效期建议 15 分钟，时间以服务端为准。结果不确定时重新查询状态，避免只凭按钮点击就显示成功。

### 4.8 我的订单与订单详情：知道下一步

订单列表页签：全部、待付款、待发货、待收货、已完成、已关闭。跨店订单按店铺显示；待付款子订单引导到所属统一支付单。

六个状态按钮统一宽高、文字居中；当前原型与商品排序共用 84 × 34 px，空间不足时整项换行。

详情顶部用状态与一句动作说明呈现下一步：例如“等待商家发货”“商家已发货，请等待收货”。下方显示商品与地址快照、金额、演示物流和时间线。

仅在有效状态显示付款、取消和确认收货按钮。首版已付款后不支持取消、退款或售后；后续实现售后后再增加入口和结果页。

### 4.9 个人中心与账号

个人中心聚合头像、昵称、订单状态入口、收货地址、个人资料，以及商家申请或工作台入口。地址页支持新增、编辑、删除与默认地址。
首版登录采用左品牌、右表单的独立桌面页，普通用户共用账号密码登录注册。正常注册登录进入买家商城或原购物上下文；头像菜单中的“商家中心”统一承接开店与经营，不要求用户注册时选择买家或商家身份。
顶栏账号菜单提供个人资料、订单、收货地址、消息、商家中心和退出；资料页可修改昵称与头像，登录账号和用户 ID 分开只读展示。
资料页「保存资料 / 取消」等宽等高、文字居中，与详情购买操作共用 112 × 40 px；操作组空间不足时整项换行。
验证码登录、找回密码、收藏、足迹等作为后续候选。具体字段、菜单与状态规则见 [登录与账号细节](07-登录与账号细节.md)。

## 5. 商家端逐页设计

### 5.1 申请开店

入口为头像菜单“商家中心”。未开店时先展示独立的开店介绍页：品牌主视觉、开店权益、准备资料、流程、常见问题和“免费开店”主按钮；“免费”仅表示本项目创建店铺不收费，不承诺其他真实经营费用。

确认开店后进入申请工作区，流程为“填写店铺资料 → 提交审核 → 开始经营”。资料先包含店铺名称、Logo、主营分类、简介；联系人或资质是否增加，在正式工程字段评审时确定，当前原型不采集真实身份材料。

| 当前状态 | 再次进入商家中心 |
| --- | --- |
| 未申请 | 开店权益与流程介绍 |
| 草稿 | 继续填写申请 |
| 待审核 | 审核进度 |
| 被驳回 | 驳回原因与修改重提入口 |
| 已通过且店铺正常 | 直接进入店铺工作台 |
| 店铺受限 | 显示原因与允许处理的已有业务 |

待审核页显示提交时间和当前状态；驳回必须带原因。未审核通过不能发布可售商品。已开店后无需反复浏览宣传页，买家与店铺经营共用登录态和个人资料。

### 5.2 工作台与导航

建议栏目：工作台、商品管理、发布商品、订单管理、店铺设置；上架助手放在 P1，完成后再显示正式入口。

顶部明确当前店铺与商家身份。首版按一个商家账号管理一家店铺组织界面；员工管理、组织体系和店铺切换后续再做，资源归属校验从首版保留。

工作台先展示四项：今日已支付金额、今日已支付店铺订单数、待发货订单数、在售商品数。点击待办或数量进入已筛选的列表。
下方展示最近订单、低库存商品与待办，不先堆满趋势图和增长率。金额属于演示交易统计，不称为可提现余额或利润。

统计口径：商家仅统计本店店铺订单；“今日”按平台时区 Asia/Shanghai，金额按支付成功时间归属日期；没有退款时不展示净成交额。

### 5.3 商品列表

页签：全部、草稿、在售、已下架。顶部名称、分类、状态筛选，右上角“发布商品”。
主要列：主图与名称、规格与价格区间、可售库存、状态、更新时间、操作。首版包含编辑、单件及批量上下架；批量逐件校验并显示结果。批量导入和批量编辑仍为后续候选。

自主下架可编辑后重新上架。平台限制售卖的商品要单独标注原因，在限制解除前不能通过普通上架操作绕过。

### 5.4 发布与编辑商品

分为基本信息、图片与详情、规格与价格、发布检查四块。保存草稿允许资料不完整，发布前就地显示缺失项。

按 D055，点击保存并成功持久化后，再次打开该草稿应回显已保存的文本、图片及顺序、已填写的规格和价格/库存，让商家继续补充；继续保存更新同一商品。未保存临时输入不自动恢复，服务端保存与回显尚未实现。

界面直接使用“商品”“规格”等词。单规格只填价格与库存，多规格填写颜色、尺寸后生成组合表格，每行分别填价格、库存和可选图片。组合不得重复，已产生订单的规格保留历史记录。

建议先保存草稿并查看预览，再正式上架；编辑已有商品时提示哪些内容会影响后续购买。库存编辑只调整可售量，已占用数量单独只读显示。

库存人工调整按 D055 保存前后数量、原因、操作者和时间；旧表单与当前库存冲突时不能无条件覆盖。记录字段、冲突返回与保存接口随详细设计确定，不新增库存管理页面。规格替换按 D057，具体保存字段与事务实现继续细化。

D057 确认第 2 项：商家替换旧规格并保存后，旧 SKU 保留并停用，新组合创建新 SKU，一次保存完成；旧规格不继续在售。旧购物车保留原规格，提示“所选商品不能购买”、商品图标变灰且禁止结算，点击进入原店铺，不自动换成新规格。库存为零仍显示已售罄，此规则替代 D056 临时文案。保存方式已确认，具体物理字段待详细设计，本轮未改 Demo。

### 5.5 订单处理

筛选包含编号、时间和状态。列表显示本店订单、商品摘要、金额、付款时间与下一步操作。
详情显示商品及收货快照、时间线和演示物流；仅待发货订单可填写物流并发货。已发货记录作为履约信息保留。

商家不能手动把订单改为已付款、已完成或随意修改成交金额。跨店支付中只看到本店部分，不看到其他店铺的商品或订单资料。

### 5.6 店铺设置

编辑 Logo、名称、简介与主营分类，查看店铺状态。首版不增加可视化装修、员工角色矩阵或资金账户。
店铺停用时突出显示原因和限制：禁止新结算，已有订单仍可按既定规则付款、查看和履约。

## 6. 平台管理端逐页设计

导航包含概览、入驻审核、分类管理、店铺管理、商品管理、订单查询。顶部始终显示“平台管理”；Agent 运行记录不加入当前菜单。

### 概览

展示待审核申请、正常店铺、在售商品、今日已支付店铺订单等有明确口径的数据。待审核和异常项可以直接进入处理列表。
平台可额外展示支付单数量，但名称与店铺订单数分开，避免一次跨店付款被误认为一次单店购买。

### 入驻审核

列表有申请店铺、主营分类、提交时间、状态；详情看完整资料与审核历史。通过时确认对象，驳回必须填写原因，商家能收到对应状态反馈。

### 分类管理

首版至多两级，支持名称、排序与启用状态。已被商品引用的分类不能直接删除；停用后禁止新发布或改分类时选用，已有商品继续展示和交易，历史分类名称保留。

### 店铺管理

按名称和状态筛选，查看资料、成员归属与商品数量；停用需填写原因。限制范围与已有订单的后续处理可在确认面板中看到，操作后保存记录。

### 商品管理

按店铺、分类、名称与状态查找，查看买家侧预览与商品资料。平台可以限制售卖或解除限制，操作附原因与记录；商家端同步展示。
不在平台后台直接代替商家编辑成交价格或绕过订单规则。

### 订单查询

按支付单、店铺订单、买家、店铺和时间追踪。详情能看“一个支付单关联哪些店铺订单”，并分别显示状态。
P0 以查询为主，不提供随意改状态、改价、退款、资金结算等入口。

### 后续候选：Agent 运行记录（暂缓）

当前不开发该页面、不创建运行记录表或接口。以后用户启用 Agent 时，再评估以下交互。

按时间、用户和成功失败筛选，显示任务摘要、工具名称、耗时、结果状态与错误摘要。支持查看脱敏调用过程，用于理解“搜索了什么、获得什么结果、在哪里失败”。
不展示密钥、无关个人信息或模型内部推理。运行记录属于平台管理页面，不默认向买家公开全部后台日志。

## 7. 后续 Agent 页面候选（暂缓）

### 后续只读导购候选：帮我淘

依据 D037，当前不开发 Agent 或悬浮球，只维护 [商城查询 API 契约](11-Agent接口预留.md)。以下保留为用户以后启用时的讨论材料，不属于商城首版交付。

入口方向仍为页面右下角悬浮球，点击展开对话面板，收起后恢复小球。悬浮球和面板不占用顶栏与搜索空间，不遮挡加购、购买、结算等主要操作，也不自动弹出。可提供示例问题，例如“200 元以内，帮我找无线键盘”。

对话显示明确的工作状态，例如“正在搜索商品”“正在核对规格”，随后返回可点击卡片和比较理由。比较涉及未提供的参数时标记“资料未提供”。
卡片点击后进入正常商品页。后续第一阶段导购建议不直接加购、下单或付款，用户在普通购物界面完成交易。

无结果时提出调整条件的建议；模型或工具故障时说明稍后重试，并保留普通搜索入口。收起对话面板不丢失当前商品页面和对话上下文。

### 后续：商家上架助手

放在发布商品表单旁边。商家提供商品事实与卖点，助手生成标题、描述、分类与属性建议，结果可逐项采纳，缺失参数列出待补信息。
价格、库存与性能不能凭空补齐；商家编辑保存草稿，按原流程确认发布。

### 更后续：规则与订单客服

规则回答有来源，订单查询限定当前用户权限。售后申请等动作在对应业务实现后再考虑。

## 8. 桌面范围与通用交互

首版买家、商家和平台三端均以桌面浏览器为设计和验收范围。当前不设计手机底部导航、手机专用流程或移动适配；窄预览区域的基本排版不代表已承诺移动端交付。
保留目前三端的布局骨架，优先完善身份区、登录、资料和真实状态反馈。

所有端共用以下体验：

- 加载状态、空数据、失败重试、无权限和离线或超时反馈。
- 表单错误放在对应字段附近，提交失败保留已填内容。
- 提交中避免重复点击；成功有可理解反馈和下一步入口。
- 下架、停用、取消和确认收货展示具体对象与影响，再由用户确认。
- 状态同时用文字与颜色表达，主要操作可用键盘到达。
- 库存、金额、商品状态和角色变化以服务端返回结果更新，避免页面显示过期状态。

## 9. 首版与后续的页面边界

首版需要真实可用的三端基础页面和跨店交易；查询 API 预留复用契约，Agent 不属于当前实现或验收。订单页不预留可点击却无结果的退款入口，商家后台也不堆放尚未实现的营销菜单。

P1 候选：收藏、评价、优惠券、商家上架助手、退款售后。P2 候选：规则客服、复杂推荐、聊天与运营活动。具体优先级之后按演示价值与工作量确定。

首页活动内容和店铺页先用固定模板；装修编辑器、直播、秒杀、多仓、商家分账等不进入当前设计主线。

## 10. 三端联动场景

商家申请开店 → 平台审核通过 → 商家发布带规格的商品 → 买家通过搜索、筛选和列表找到商品 → 两家店商品加入购物车 → 提交结算生成两个店铺订单 → 统一模拟付款 → 商家分别发货 → 买家分别收货 → 平台追踪交易。

这条流程决定每一页的入口、主要操作和结果页。评审时逐页检查“从哪里来、能做什么、完成后到哪里去”，再细化颜色、间距与动效。

当前已完成会话内桌面 Demo，并修复整栏收起后商品区仍保留空位的问题。原型与正式开发的差距、已验证路径见 [原型进度与文档维护](09-原型进度与文档维护.md)。界面调整先讨论达成一致再实施；文档随已确认变化同步。

## 14. 新交互的具体约定

### 地址、提交与付款

结算没有地址时提供添加入口并禁用提交。地址维护与购物路径相连；已有订单保留提交时的收货人、手机号和地址，不受后来编辑或删除地址簿影响。当前仅填写虚构信息。

提交时按店铺生成待付款订单，并用同一个支付单关联；统一付款后各店独立发货。取消作用于整次结算，确认面板说明涉及的订单数。取消或超时会释放本地演示库存，已关闭的结算不能再次付款。有效期使用本机时钟，正式工程必须改为服务端时间与状态。

待付款子订单通过“去统一付款”进入所属支付单。结果页显示已付金额、店铺订单和继续购物入口；平台查询只能查看，不展示买家的收货操作。

### 商品编辑与图片

商品草稿不展示给买家；发布前校验名称、介绍、图片及每条规格的价格/库存。图片库最多选 3 张，可调整主图与移除。两个规格维度每组最多 3 项，重新生成时保留同名组合已有价格和库存。离开未保存页面前提示。

图片库与主图调整已经浏览器检查。本机 JPG/PNG 文件预览入口已写入原型，但本轮自动浏览器检查等待文件选择器超时，未完成验证；它不上传服务器，也不承诺刷新保留。正式 OSS 上传尚未实现。

素材、提示词与生成方式见 [演示素材说明](../frontend/assets/demo/README.md)。颜色图片未逐 SKU 单独制作，详情明确按所选规格说明确认颜色；局部放大不冒充独立细节照片。

### 消息、平台与演示工具

打开消息面板不自动将全部消息读完；点击某条详情后标为已读，也可主动全部已读。审核与发货消息进入具体记录，缺失历史记录时显示可返回的空状态。

平台限制商品或停用店铺需填写原因，买家新购买入口和商家售卖状态随之变化；已有订单仍按原有规则查看和履约。解除限制同样填写原因。本地模拟的场景切换不等于正式授权。

顶部“状态示例”属于产品外的评审工具，提供商品加载、加载失败、下一次提交失败、付款超时、登录过期与恢复正常。商品请求和提交等待均为本地展示，不发起网络请求。当前还没有覆盖正式服务的所有失败方式。

评审依据：[NN/g 可用性原则](https://www.nngroup.com/articles/ten-usability-heuristics/)与 [W3C 表单通知建议](https://www.w3.org/WAI/tutorials/forms/notifications/)。具体功能范围以用户确认及决策记录为准。
